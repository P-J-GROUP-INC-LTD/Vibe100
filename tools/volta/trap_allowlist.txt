# tools/volta/trap_allowlist.txt - every kernel whose sm_70 SASS contains BPT.TRAP and why that is acceptable.
#
# Format (tools/volta/sass_audit.py): one entry per line, `regex<TAB>justification`.  The regex is searched in the
# DEMANGLED kernel name (with its parameter list).  The justification must name the host-side guard (file:function)
# that keeps the kernel from ever being launched on a compute-capability-7.0 device; the guards were read in the
# source, not assumed.  `# `-lines and blank lines are ignored.
#
# A trap is not a bug in itself: nvcc compiles a body that needs a newer instruction (or ggml's NO_DEVICE_CODE) to
# `__trap()` so that the object still links.  It is a bug when the host can launch it - see docs/volta/ and
# tools/volta/dispatch_audit.md for the audit of every such decision.
#
# EVIDENCE for the ggml entries (3cf03257f219afbe7334045ff7c6a06ac68c627d, the pin in CMakeLists.txt): on the upstream
# build for sm_70 the 144 trapping mul_mat_q instantiations (9 types x 16 widths) are EXACTLY the (type, J, fallback)
# triples absent from ggml_cuda_mmq_get_config_ampere's CASE table (checked by script: observed == expected, 144 of
# 144), i.e. exactly the ones mul_mat_q_switch_J skips.
^void mul_mat_q<\(ggml_type\)\d+, (24|40|48|56|72|80|88|96|104|112|120), true>	ggml MMQ tile width J that the cc>=7.0 config table has no entry for with fallback=true (the table, ggml-cuda/mmq-config-ampere.cuh, lists only J = 8,16,32,64,128): the kernel body is `if (ggml_cuda_mmq_get_config(type,J,fallback).type == GGML_TYPE_COUNT) { NO_DEVICE_CODE; return; }` (mmq.cuh mul_mat_q).  Never launched: mul_mat_q_switch_J (mmq.cuh) only picks a J whose config.type != GGML_TYPE_COUNT, and Strata reaches it through strata::prefill::mmq::Context::run (src/prefill/moe_mmq.cu) with cc = 100*major+10*minor = 700 (src/prefill/ggml_cuda_host.cu:ggml_cuda_info), so the host reads the same table the device compiled (ggml_cuda_highest_compiled_arch(700) >= GGML_CUDA_CC_VOLTA -> ampere table).
^void mul_mat_q<\(ggml_type\)\d+, (56|72|88|104|120), false>	same as above for fallback=false (the table lists J = 8,16,24,32,40,48,64,80,96,112,128 only).
^void quantize_mmq_nvfp4<	NVFP4 activation quantizer: body is `#if defined(BLACKWELL_MMA_AVAILABLE) ... #else NO_DEVICE_CODE` (ggml-cuda/quantize.cu:quantize_mmq_nvfp4).  Only launched by the NVFP4-weight branch of quantize.cu; Strata's MMQ entry points never reach it: src/prefill/moe_mmq.cu:supported() has no NVFP4 and mmq::quantize calls quantize_mmq_q8_1_cuda only.
block_scores_tc_kernel	3xTF32 mma needs sm_80 (qsa_select.cu: STRATA_SEL_SM80).  Host guard: qsa_select.cu:qsa_block_scores_tc returns false when cudaDevAttrComputeCapabilityMajor < 8, and prefill.cpp (the only caller) then runs the FP32 warp kernel qsa_block_scores.
prompt_attn_kernel<(0|1|3)>	upstream tensor-core prompt attention, v1 kernel (KV mode 0 fp16 / 1 int8 / 3 K8V4): its mma.m16n8k16 compiles to __trap() below sm_75 (qsa_prompt_attn.cu: mma16816, STRATA_PA_SM80).  Host guard: qsa_prompt_attn.cu:select_impl (used by qsa_prompt_attn_batch) keys on cc = major*10 + minor and returns PaImpl::V1 only for cc >= 75; cc 70/72 get prompt_attn_volta_kernel or false (STRATA_VOLTA_ATTN=0), after which prefill.cpp falls back to qsa_decode_attn_batch (FP32).  (Upstream 0.1.31 keyed on cc_major alone and launched launch<1> on a V100: the sm_70 crash this port fixed.)  Audit round (dispatch_audit.md R7b): the same stubs are what an sm_70-ONLY build runs on a cc >= 7.5 card (sm_70 SASS on a 7.5, the compute_70 PTX JIT-compiled on 8.x); select_impl (used by qsa_prompt_attn_batch and qsa_prompt_attn_variant) returns PaImpl::V1 only when cudaFuncGetAttributes(prompt_attn_kernel<1>).ptxVersion (= __CUDA_ARCH__/10 of the code the driver runs on that device) is >= 75: for this sm_70 code (cubin on cc 7.0-7.5, compute_70 PTX JIT on 8.x) it is 70, so every such card gets prompt_attn_volta_kernel (or false with STRATA_VOLTA_ATTN=0); if the query itself fails the card's cc decides, as upstream.  device.cu also refuses to start such a build.
prompt_attn_i8_kernel	upstream cp.async + m16n8k16 kernel for int8 KV (needs sm_80: qsa_prompt_attn.cu cp_async16 / mma16816).  Host guard: qsa_prompt_attn.cu:select_impl returns PaImpl::I8CpAsync only for cc >= 80 (and int8 KV).  Audit round (dispatch_audit.md R7b): select_impl returns PaImpl::I8CpAsync only for cc >= 80, int8 KV, STRATA_PROMPT_ATTN_V1 unset and cudaFuncGetAttributes(prompt_attn_i8_kernel).ptxVersion >= 80 (cp_async16 is a trap in sm_75 code as well, so a 70;75 build on Ampere takes v1).
